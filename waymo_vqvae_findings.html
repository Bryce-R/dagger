Key Findings

  • The original VQ baseline reached only pos_loss ~= 0.147 at best after 10k epochs.
  • Plain FSQ collapsed without a learnable pre-tanh affine adapter; effective bin perplexity stayed around ~2.
  • Adding learnable FSQ input scale/offset fixed the collapse on CPU and reached the < 0.001 target.
  • Annealing quantization is not the main win. The learned affine adapter is the main win.
  • MPS is available only outside the sandbox. It trains much faster but follows a different optimization path.
  • The MLP architecture removes the large CPU/MPS gap seen with Conv1D, but it does not yet beat the best Conv CPU run.
  • Validation metrics show the MLP/FSQ runs overfit heavily. Same-data max-error results were optimistic before the train/val split.
  • For dynamic-state MLP runs, --position-loss-weight 0 produced better same-data max-error tails than 10, but validation still diverged.
  • Dropout regularization did not fix validation. Dropout 0.05 helped early validation at epoch 1000, but final validation degraded; dropout 0.2 underfit and was worse.

The diagnostic suggests MPS drives encoder latents to very large magnitude, saturating tanh in FSQ. Smaller MPS batch size and smaller initial FSQ input scale helped somewhat but did not close the CPU gap.

Recommended Next Experiments

  1. Add best-validation checkpointing / early stopping and evaluate the saved best epoch, not only final weights.
  2. Try smaller MLP capacity, e.g. --hidden-dim 128 or 256, because validation suggests memorization.
  3. Try data expansion: more Waymo shards and/or --include-all-valid-tracks.
  4. Try lighter latent-capacity variants after checkpointing, e.g. --code-dim 32 or lower FSQ levels.
