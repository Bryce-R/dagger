Key Findings

  • The original VQ baseline reached only pos_loss ~= 0.147 at best after 10k epochs.
  • Plain FSQ collapsed without a learnable pre-tanh affine adapter; effective bin perplexity stayed around ~2.
  • Adding learnable FSQ input scale/offset fixed the collapse on CPU and reached the < 0.001 target.
  • Annealing quantization is not the main win. The learned affine adapter is the main win.
  • MPS is available only outside the sandbox. It trains much faster but follows a different optimization path.
  • The MLP architecture removes the large CPU/MPS gap seen with Conv1D, but it does not yet beat the best Conv CPU run.
  • Validation metrics show the MLP/FSQ runs overfit heavily. Same-data max-error results were optimistic before the train/val split.
  • For dynamic-state MLP runs, --position-loss-weight 0 produced better same-data max-error tails than 10, but validation still diverged.
  • Dropout regularization did not fix validation. Dropout 0.05 helped early validation at epoch 1000, but final validation degraded; dropout 0.2 underfit and was worse.
  • The best validation-gap fix so far is not more epochs: use --include-all-valid-tracks, reduce capacity to roughly hidden=128, code_dim=16, fsq=64, and select the best validation checkpoint.
  • Light denoising input noise helped slightly. --input-noise-std 0.02 gave the best validation loss among the new regularized runs; 0.05 was more stable at the final epoch but had a worse best checkpoint.

Corrected takeaway: compare tokens as one token per timestep with joint XY vocabulary. The fair 50-token, 2500-vocab comparison is global 50x50 XY bins versus FSQ with --mlp-latent-tokens 50 --code-dim 2 --fsq-levels 50. In that setup FSQ wins average validation loss (0.037426 vs 0.110475), but the naive bins have a much tighter max-error bound (about 1.47m at every second, versus FSQ peaking above 14m). Adding a top-10% tail loss and final-step loss makes FSQ much better for sparse examples: val loss drops to 0.014194 and the 5s max error drops to 5.52m. Direct bins still have the tighter hard max-error bound. Direct bins with larger vocab, e.g. 256x256 per timestep, are a different budget and remain much stronger on both average and tail absolute XY error. Training with absolute XY as the only reconstruction objective works even better on average: --decode-absolute-positions --reconstruction-loss-weight 0 --position-loss-weight 1 reaches val pos_loss=0.012602, and adding tail/final absolute-position terms reaches 0.011651.

Variable-Length Segment and Residual Tokenizers, 2026-05-18

Fixed timestep tokens are a poor compression target for simple trajectories: cruising for 5 seconds should need one semantic token, while brake-then-accelerate may need two. The new DP experiment searches for the fewest piecewise motion segments that reconstruct the 2Hz trajectory under a rate-distortion objective. Degree 1 means constant velocity; degree 2 means constant acceleration.

Main takeaway: variable-length piecewise tokens are the strongest direction. The hand-fit DP oracle proves that most 2Hz vehicle futures are simple enough for roughly one constant-acceleration segment. A learned boundary model already preserves the early-horizon p99 target, but it is not yet as token-efficient as DP. Residual FSQ is useful as a learned correction baseline, but it behaves like iterative refinement rather than semantic compression.

Recommended Next Experiments

  1. Add best-validation checkpointing / early stopping and evaluate the saved best epoch, not only final weights.
  2. Try smaller MLP capacity, e.g. --hidden-dim 128 or 256, because validation suggests memorization.
  3. Try data expansion: more Waymo shards and/or --include-all-valid-tracks.
  4. Try lighter latent-capacity variants after checkpointing, e.g. --code-dim 32 or lower FSQ levels.
